Disk images & updates

Pascal is installed at T:/apps/zpascal.bin with its libraries in T:/lib/. Updating an image replaces all of its contents and restarts Zeal. Save personal programs as new H:/work/ files first. H: files are kept; unsaved editor RAM is lost. H: backups do not include disk images.

Moving from an older book setup? Before replacing T:, open T:/src/pascal/UNTITLED.pas (if present) and any other personal T: sources with W in Pascal, then use A (Save As) to copy each to a new H:/work/ file. H: downloads do not back up T:. Update TF and EEPROM together to install Pascal on T: and refresh the startup paths. Older H:/bin and H:/lib files are left intact.

Always save your own programs as new files under H:/work/. Use W for a new file, or A (Save As) before editing a starter. Lesson starters are loaded when Zeal starts.

Starter updates fetch the latest published code into H:/book/lab in OPFS. Imports create new folders under H:/work/. Neither action changes your other H: files. Keep downloaded backups: clearing site data removes browser saves.

Where are my saved files and disks?

H: uses the browser's Origin Private File System (OPFS), in the zeal-pascal-book folder. It is separate from Local Storage and IndexedDB. In Chrome's DevTools Console, list its contents with:

const h = await (await navigator.storage.getDirectory()).getDirectoryHandle('zeal-pascal-book');
for await (const [name, handle] of h.entries()) console.log(name, handle);

Saved files survive reloads at the same site address, but the IDE does not automatically reopen an arbitrary H: file: use W and enter its path. The TF/EEPROM images are stored separately under zeal-native/<book namespace hash>/ in OPFS. Its manifest maps TF and EEPROM to their image files. This project shares the same disks across chapters; another project uses its own namespace. These images do not appear in Local Storage or IndexedDB.
