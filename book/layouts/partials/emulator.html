Files, backups & fresh starts

Use S in Pascal to save source. H: files and completed writes to the TF card (T:) and EEPROM (B:) persist automatically in OPFS. No separate Save Data action is needed. Editor text still in RAM is not saved. Clearing site data removes browser saves.

Fresh starts and imports create new folders. They never overwrite your earlier work. Reload the page to restart the computer after saving in the IDE. Community tools are on T:. B:/autoexec.zs configures their paths and H:/bin/. The shell starts in H:/ so typing zpascal finds its compiler library. H: backups do not contain the TF or EEPROM disk images. Restore startup EEPROM replaces B: with the book defaults and restarts Zeal; it keeps T: and H: but discards unsaved guest RAM.

Where are my saved files and disks?

H: uses the browser's Origin Private File System (OPFS), in the zeal-pascal-book folder. It is separate from Local Storage and IndexedDB. In Chrome's DevTools Console, list its contents with:

const h = await (await navigator.storage.getDirectory()).getDirectoryHandle('zeal-pascal-book');
for await (const [name, handle] of h.entries()) console.log(name, handle);

Saved files survive reloads at the same site address, but the IDE does not automatically reopen an arbitrary H: file: use W and enter its path. The TF/EEPROM images are stored separately under zeal-native/<book namespace hash>/ in OPFS. Its manifest maps TF and EEPROM to their image files. This project shares the same disks across chapters; another project uses its own namespace. These images do not appear in Local Storage or IndexedDB.
