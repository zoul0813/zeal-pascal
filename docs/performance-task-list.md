Language support is the accepted baseline; overlays remain deferred.

The pre-optimization full revised acceptance plan passes. PERF01–PERF07 are complete. PERF08 is next. The order ranks expected practical benefit: savings, how often the path runs, confidence, and the size of the change. It is not a numerical sort of unrelated worst-case percentages. Reference-heavy programs may benefit most from PERF02; every successful compile benefits from PERF01. The first-four measurement checkpoint below retains PERF05 as next; re-evaluate remaining estimates as native evidence arrives.

Savings below are projections for the audit fixtures, not achieved speedups. A million nominal Z80 T states is 0.1 seconds at an illustrative 10 MHz; this excludes SHA time, bank wrappers, C setup and OS waits. Estimates overlap and must not be added.

## Actionable tasks

### PERF01 Skip overwritten runtime zeroing

- [x] Initialize page0's runtime prefix directly from the verified template and zero only its remaining tail.

Owner: `src/compiler_compile.c`. At the audited build, the runtime occupies 16,191 bytes and leaves 193 bytes to clear. Derive the boundary from the existing runtime size; do not hardcode these artifact sizes. Keep other pages, globals and gaps initialized, and preserve cancellation and failed-allocation cleanup.

Done when: RAM, COM and CHN image/map bytes match baseline for unchanged inputs; native ownership/cancellation checks pass; the removed stores and native compile cycles are recorded. Do not extend this to staging-page zeroing.

### PERF02 Stop reference comparisons at first mismatch

- [x] Compare stored reference-position bytes directly and stop at the first unequal byte.

Owner: `src/compiler_sources.c`. Keep the first matching ID, all six context bytes, downward job layout and catalog collision checks. Add no index or page. One-file capacity remains 1,619 at the audited layout; its sequential fixture models 5,239,084 reads becoming 1,314,109. This is a capacity-case estimate, not a typical compile saving.

Done when: repeat includes with different switches, duplicate references, one/two-source exhaustion and diagnostic replay pass; generated artifacts match; a representative symbol-heavy compile has before/after native timings.

### PERF03 Hash and validate source capture together

- [x] Produce the raw digest and canonicality result in one capture pass; preserve the snapshot fallback.

Owners: `snapshot_record` in `src/compiler_job.c` and the existing hashing/validation owner in `src/compiler_job_wire.c`. Canonical text must satisfy line limits, CR/byte26 rules and trailing-space rules. Preserve independent worker and post-worker authentication. Limit this task to the adjacent duplicate capture computations.

Done when: canonical, noncanonical, empty, trailing-space and malformed cases preserve digests, ownership and error behavior; the canonical 16 KB fixture uses one capture hash instead of two and roughly 16,000 reads instead of 48,000.

### PERF04 Reuse lexer bytes

- [x] Read each identifier character once and reuse it for classification and token accumulation.

Owner: `src/compiler_front.c`. Start with identifiers; leave numeric/comment rewrites for a later measured extension. Preserve explicit cancellation at bounded byte intervals when reducing `get` calls. BANK4 had only 32 spare bytes at the audited baseline; current measured space is recorded below.

Done when: long and mixed letter/digit identifiers, case handling, closing `.)`, source positions and cancellation tests pass; generated artifacts match; letter/digit reads reach one per character apart from termination/lookahead.

### PERF05 Resolve symbol references once per comparison

- [x] Move reference-position decoding outside each candidate symbol's character loop.

Owner: name comparisons in `src/compiler_front.c`. Keep full identifier significance, case folding, scope order, With-field precedence, shadowing and invalid-reference checks. Keep this first change narrow; do not add persistent fingerprints or redesign the symbol table.

Done when: nested scopes, long common-prefix names, includes and built-in shadowing pass; ten-character complete comparisons require 94 rather than 130 far reads; BANK4 remains within bounds. Consider lookup-local source-descriptor reuse only as a follow-on.

### PERF06 Walk wire tables once during lookup

- [x] Give the wire-view branch of `sources_find` one sequential decode cursor.

Owner: `src/sources.c`. Continue validating every decoded record. Return the earlier match or not-found at the first malformed record; keep lifetime/version checks local to this nonpolling call. Do not retain cursors across include processing. Leave ordinary owned catalogs unchanged.

Done when: first/last/missing names, malformed middle records and arbitrary IDs preserve results; ten-record reads drop from 3,025 to 550. The 86-record fixture is a table-capacity test using nonresident descriptors, not a feasible count of resident editor pages.

### PERF07 Skip equal-length edit tail copies

- [x] Separate equal-size replacement from growing and shrinking edits so unchanged suffix bytes are never rewritten.

Owner: `source_replace` in `src/source.c`. Retain pre-store validation and cursor, previous-position, dirty, revision and mutation tracking. This improves overwrite and same-length replacement; default insert-mode typing still shifts a tail.

Done when: editor/source tests and rejected edits pass; middle overwrite in the 16,000-byte fixture removes 7,999 reads and writes; native overwrite latency improves.

### PERF08 Gate unnecessary source-resume calls

- [ ] Call `cc_source_resume` only when its existing included-EOF precondition holds.

Owner: `cc_next` in `src/compiler_front.c`. Keep include switch restoration, EOF handling and error precedence identical. This is independent of PERF04, but apply and measure it after that change so their contributions remain distinguishable.

Done when: repeated includes, empty includes, root EOF and option restoration pass; unnecessary resume calls disappear; linked BANK4 still fits.

### PERF09 Hash canonical source in one traversal

- [ ] Replace line rescanning with pending-space accounting in `source_hash`.

Owner: `src/source_hash.c`. Hash pending spaces only when a later nonspace proves they are not trailing; discard them at newline/EOF. Preserve exact canonical bytes. Do not combine source snapshot changes into this task.

Done when: independently computed digests match for empty/all-space lines, trailing spaces, tabs, high bytes and final newline/no newline; source-map lookup passes; the 16 KB fixture falls from 32,000 to 16,000 source reads. Recalculate aggregate benefit after PERF03.

### PERF10 Prove a bounded native far-read helper

- [ ] Add the smallest retained helper that copies one bounded far span into resident memory, with native preservation probes.

Owner: the retained mapping core in `src/native.asm`. Bound source extents and near buffers; handle zero explicitly; restore the MMU before returning, polling, callbacks or OS calls. Split caller work at page boundaries. Preserve SP, IFF and calling convention. Resident code has 175 spare bytes; static data has only 60. Use an explicitly owned stack or existing safe buffer rather than assuming room for a new global buffer.

Done when: zero/one/boundary spans and MMU/SP/IFF probes pass and the linked resident window fits. No production consumer is required in this task.

### PERF11 Use far-read spans in job stream hashing

- [ ] Feed `job_hash_stream` through PERF10 in bounded chunks, retaining the existing SHA computation and stream validation.

Owner: `src/compiler_job_wire.c`. Start with this one consumer. Preserve normalized-zero windows, exact lengths and both raw/normalized call behaviors. SHA block work does not decrease.

Done when: raw and normalized digest vectors, tampered replies and descriptor/page rejection pass; generated artifacts match; stream hashing improves in native cycle measurements. Record a separate follow-up for other hash/load consumers only if this experiment succeeds.

### PERF12 Prove a versioned native fill helper

- [ ] Add a bounded retained fill operation that participates in the existing mutation/version protocol.

Owner: the retained mapping core. PERF10 should establish the mapping/preservation pattern first. Keep actual stores visible to every page-version consumer, preserve overlap-independent bounds and counter behavior, and bound chunks so callers can maintain cancellation. Do not reuse the non-versioned chain transport unchanged.

Done when: native zero/one/full-span probes, MMU/SP/IFF preservation and stale-build/catalog rejection pass, with no layout overflow. No production caller is required yet.

### PERF13 Fill compiler image pages in spans

- [ ] Replace per-byte zero loops in `compile_project` and `cc_image_page` with PERF12.

Owners: `src/compiler_compile.c`, `src/compiler_build.c`. Depends on PERF01 and PERF12. Retain lazy page1 allocation and all initialized-byte guarantees. Keep polls between bounded chunks. After PERF01, the fill model applies to 32,961 bytes, not 49,152.

Done when: generated RAM/COM/CHN and maps match; allocation-failure/cancellation tests and native job adoption pass; measured cycles improve. Recompute savings from the implemented helper instead of carrying forward the 7.75-million-T estimate automatically.

### PERF14 Move editor tails with bounded native spans

- [ ] Add a versioned same-page move and use it only for `source_replace` tail shifting.

Owners: retained mapping core and `src/source.c`. Reuse PERF12's preservation/version proof where it fits. Respect forward/backward overlap direction; keep complete edit validation before the first store and preserve editor interruption behavior. Leave cross-page moves and block composition outside this task.

Done when: growing/shrinking edits at both ends and boundaries, overlapping shifts, failed edits, undo and build invalidation pass; native insert-mode latency improves. The 5.79-to-0.34-million-T estimate describes the shift alone, not total key latency or validation.

### PERF15 Avoid source redraw on cursor-only movement

- [ ] Add a narrow path that updates only cursor/status when text, selection and viewport are unchanged.

Owner: the edit/render loop in `src/main.c`. Keep full redraw for scrolling, selection changes, text changes, external output and uncertain state. Do not begin with a general dirty-row cache; BANK1 and BANK13 are nearly full.

Done when: native IDE screen checkpoints show identical status/cursor/selection behavior, cursor-only moves emit no source rows, and cycles per move decrease. Treat cached line counting and incremental typing as separate follow-ons.

### PERF16 Calculate both parent digests in one traversal

- [ ] Compute normalized and raw stream hashes together inside parent success validation, while checking both.

Owner: `src/compiler_job_result.c`. Reuse PERF10/11 where appropriate, but recompute the saving against their faster reader. Keep raw digests until bundle page vectors/lengths/roles match. Budget an additional SHA state and held digests against actual peak stack use.

Done when: all reply mutation tests pass, both digests remain independently checked, and parent validation uses one read traversal per image/map pair. The original 1.81-million-T estimate uses byte accessors and will be smaller after PERF11. Do not fuse worker sealing/raw hashing: those cover different byte snapshots.

### PERF17 Validate only changed source lines

- [ ] First establish validity tied to page lifetime/version, then validate replacement text and affected line boundaries only.

Owner: `src/source.c`. Preserve a full-validation fallback when old-text validity is unknown or external mutation is detected. Keep total-capacity, 127-character line, CR and byte26 checks before mutation. Do not assume all old text is valid merely because an edit starts in the editor.

Done when: malformed old buffers, external stores, line joins, multi-line paste, 127/128 boundaries and rejected edits behave correctly; small-edit validation reads are bounded by affected text. Retain full source/editor regression coverage. Schedule after the simpler edit fixes because the validity proof is more involved.

### PERF18 Fold negative integer literals

- [ ] Emit the negated integer literal directly at factor parsing, preserving existing overflow and special cases.

Owner: `src/compiler_expr.c`. BANK6 has only 14 spare bytes. Establish a measured placement plan first if the change cannot fit. Preserve `-32768`, hexadecimal handling, precedence and numeric diagnostics. Defer emission rather than rewinding emitted code. Keep binary constant folding outside this task.

Done when: integer-boundary and diagnostic tests pass, native outputs and logical source-map coverage remain correct, and eligible sites save seven generated bytes. Record both compiler bank growth and generated-program shrink; expected binary identities change for this code-generation task.
