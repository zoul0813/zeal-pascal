# Review of `color-20261104`: native color and cursor extension

**Result:** I found no established correctness, calling-convention, or memory-safety defects in the supplied code. There are four actionable findings (three test gaps and one documentation gap), plus three open questions. Finding 1 could expose a compiler defect, depending on `compiler_types.c`.

## Established findings

### 1. Medium: direct color bounds are documented but untested
- **Location:** `tests/native/colors.pas` (`first=Black;last=White; type color=first..last`), `docs/runtime-specification.md` ("bounds"), and `cc_predefined_color` callers
- **Trigger and impact:** The fixture only reaches a subrange through user-declared constants. `type c=Black..White`, `array[Red..White] of ...`, `set of Black..White`, and `case n of Red:` are not exercised. If the type parser identifies a subrange start from `S_CONSTANT` symbols before calling `cc_constant`, the documented forms could fail at compile time.
- **Evidence:** The diff adds color handling to `cc_constant`, `factor`, and Inline `data()`. `compiler_types.c` and the case-label parser were not supplied, so I can't confirm either path.
- **Fix:** Add positive compile-and-run cases for all four forms, including a negative bound such as `-Red..White`. If one fails, route it through `cc_predefined_color` after user lookup.

### 2. Medium: attributes on rows exposed by scrolling are not checked
- **Location:** `tests/native/colors.pas`, the `GotoXY(80,40);write(Con,'Z')...write(Con,'N')` sequence
- **Trigger and impact:** That sequence wraps at the bottom row, but the test checks only `WhereX` and `WhereY`, then `ClrScr` resets the scroll state. Before this change, the supported routines always used a black background, so a stale attribute on a blank cell was not visible as a background color. With 16 backgrounds, a stale attribute would appear as a wrong-colored row.
- **Evidence:** No check samples the new bottom row after the wrap. `crt_blank` guarantees current attributes only for CRT-generated blanks, not for kernel or hardware scrolling.
- **Fix:** After a bottom-row wrap under a non-black background, read physical row `(A3+39) mod 40`, or the correct row for the post-scroll offset, and assert its characters and attributes. Test both `Con` and ordinary stdout. If the row is stale, either document that as a limitation or decide who owns clearing it.

### 3. Low: several supported paths have no direct test
- **Location:** `tests/native/colors.pas`, `tests/native/crt-main.c`, and the README example
- **Evidence:**
  - No I+ test covers a query failure. The I+ mode test uses only `clrscr`.
  - `TextColor` and `TextBackground` are not tested in an unsupported video mode. The pending-I/O case is covered, but the mode case is not.
  - `WhereX` and `WhereY` are never used as `Write` arguments, although the README example does this.
- **Impact:** The code review supports these paths, because they share `crt_enter` and `IOCALL`. Their documented behavior still has no regression protection.
- **Fix:**
  - Add `checked_error("begin port[$9C]:=1;delay(25);\nif wherex=0 then end.",0x20,"wherex")`, restoring the mode as the existing test does.
  - Add an I- setter check in mode 1 that confirms A5 and A8 are unchanged and IOResult is `$20`.
  - Compile and run the README example, plus a formatted `WhereX:3`.

### 4. Low: `GotoXY(WhereX,WhereY)` can fail at pending wrap
- **Location:** `cc_crt_statement` (X is always limited to 1..80), `README.md`, and `docs/runtime-specification.md`
- **Trigger and impact:** After output ends at column 80, a saved position has X=81. Restoring it with `GotoXY` raises runtime error 91, even under R-.
- **Evidence:** WhereX=81 is an intentional part of this assignment, so this is a documentation gap rather than a behavior defect. The docs do not mention the save-and-restore consequence.
- **Fix:** State this explicitly in both documents and add a short test or example showing the expected handling.

## Hand-checked by inspection

I traced these paths by hand and found no problems. I did not run anything.

- **`IOCALL` contract:** HL, DE, and flags reach the helper intact. BC and HL are clobbered on return, and both the normal and I- paths land correctly with SP at the query's result slot.
- **Query code:** The two-byte slot is zeroed before the call, the helper writes the byte result through DE, and `pop hl` balances the stack and `cc.temporaries`. A failed query returns 0.
- **Setter code:** Opcodes, nibble masks, the rotate-based A8 swap, and enum, name-table, and cache indexes are all consistent.
- **Mapper and IFF:** Query and setter helpers use the existing save and restore path without remapping page 1, and the mode check runs before anything is pushed.
- **Shadowing:** All color and query paths are gated on `id<0` or `cc_lookup()>=0`, so user declarations take precedence.
- **Moved code:** The `crt_engine` logic matches the removed code apart from the additions. The `gotoxy` and `delay` range arguments are unchanged.
- **Test arithmetic:** The `colors.pas` checks total 1729, and the 15 expected sleep arguments match the two added `Delay` calls across RAM and COM.
